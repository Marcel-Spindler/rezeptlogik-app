## Kontext

Die App organisiert Features in `src/features/<name>/` mit separaten Dateien für Types, Logik und UI. Datenquellen werden über Hooks (`usePlanningOasisData`, `useAppData`) geladen. Firestore wird für Live-Updates genutzt (onSnapshot Pattern). Google Sheets werden als CSV via `gviz/tq?tqx=out:csv` exportiert.

## Architektur: `src/features/gsheet-monitor/`

Ein generischer, erweiterbarer GSheet-Monitor-Service mit:
1. **Registry** — zentrale Konfiguration aller zu überwachenden Sheets
2. **Poller** — generischer Polling-Mechanismus (intervallbasiert)
3. **Parser** — Sheet-spezifische Parser (RTI ist der erste)
4. **Hook** — `useGSheetMonitor()` für React-Komponenten
5. **Event-System** — Custom Events für Änderungs-Benachrichtigungen

## Implementation

### Schritt 1: Types (`src/features/gsheet-monitor/gsheetTypes.ts`)
```
- GSheetConfig { id, name, sheetTab, pollIntervalMs, parser }
- GSheetSnapshot { timestamp, hash, rows, parsed }
- GSheetChange { sheetId, prevHash, newHash, changedRows, timestamp }
- RTI-spezifische Types (RtiMealBlock, RtiSubRecipeEntry)
```

### Schritt 2: Registry (`src/features/gsheet-monitor/gsheetRegistry.ts`)
```
- Zentrale Map aller Sheets: { rti: { id: "1-brEn6...", tab: "rti", interval: 30s } }
- Erweiterbar: einfach neuen Eintrag hinzufügen für zukünftige Sheets
- Sheet-IDs + Tab-Namen konfigurierbar
```

### Schritt 3: Fetch & Diff (`src/features/gsheet-monitor/gsheetPoller.ts`)
```
- fetchSheetCsv(config) → CSV-Text
- hashContent(csv) → schneller MD5/SHA-1 via SubtleCrypto
- diffRows(oldRows, newRows) → { added, changed, removed }
- Generischer Polling-Loop mit AbortController für Cleanup
```

### Schritt 4: RTI Parser (`src/features/gsheet-monitor/parsers/parseRti.ts`)
```
- Parst die RTI-CSV-Struktur (Meal-Blöcke mit Sub-Recipes)
- Erkennt: FV-Code, Planned Target, Actuals, Delta
- Pro Sub-Recipe: WO-Nr, Name, Plating Holding, RTI Plating Kg, produzierte Menge
- Status-Erkennung: "done" vs. offen
```

### Schritt 5: React Hook (`src/features/gsheet-monitor/useGSheetMonitor.ts`)
```
- useGSheetMonitor(sheetKey) → { data, lastUpdate, changes, isPolling, error }
- useRtiMonitor() → typisierter Wrapper mit RTI-Daten
- Lifecycle: startet Polling bei Mount, stoppt bei Unmount
- Änderungs-Notifications via Toast/Event
```

### Schritt 6: Integration in WhatIfView
```
- RTI-Gap Szenario nutzt live RTI-Daten wenn verfügbar
- Auto-Fill: rtiPlannedMeals, rtiActualMeals aus Sheet
- Pro Sub-Recipe: Holdings automatisch aus "Plating holding Kg" befüllen
- Visueller Indikator: "Live aus GSheet · Letzte Aktualisierung: vor 30s"
```

### Schritt 7: Standalone RTI Dashboard (optional, collapsible im Header)
```
- Kompakte Live-Ansicht aller Meal-Blöcke aus dem RTI-Sheet
- Ampel pro Meal: grün (on track), gelb (leicht hinter), rot (kritisch)
- Expandierbare Sub-Recipe Details mit Status
```
