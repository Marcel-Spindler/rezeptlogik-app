### Gefundene Fehler / Probleme

#### 1. **Bug: `utilizationPct` in KetEquipmentPanel ist hardcoded auf 8h Schicht**
`KetEquipmentPanel.tsx:28` — `const shiftMin = 8 * 60;` ist hart codiert. Wenn Schichten kürzer/länger sind oder das `SHIFT_HOURS`-Konzept aus `ketEquipmentSummary.ts` geändert wird, divergiert die UI.

#### 2. **Bug: `runSharePct` immer hardcoded 70/30**
`ketEquipmentSummary.ts:487` — `runSharePct: run === 1 ? 70 : 30` ist fest verdrahtet, obwohl `computeRunAssignments` einen konfigurierbaren `firstRunPct`-Parameter akzeptiert. Die tatsächliche Aufteilung kann anders sein (z.B. 50/50), wird aber im Summary immer als 70/30 angezeigt.

#### 3. **Potenzielle Division durch 0 in `computeRunAssignments`**
`ketRunLogic.ts:100` — `Math.max(0, ...dayRows.map(r => r.targetPortions))`: Wenn `dayRows` leer ist, gibt `Math.max(0)` → 0 zurück. Das ist korrekt, aber `threshold = weekTotal * (firstRunPct / 100)` bei `weekTotal = 0` ergibt 0, und `cumulative < threshold` (0 < 0) ist false — alle Tage würden als Run 2 markiert. Nicht erreichbar in der Praxis (Filterdurchgang), aber ein Edge Case.

#### 4. **UI: `woDetails` im KetEquipmentPanel basiert auf `row.key`-Matching für runFilter, aber `key` in woDetailsByStation ist der Station-Name**
Funktioniert korrekt, aber die Duplikat-Erkennung fehlt: Wenn eine WO dieselbe Station mehrfach hat (via Components), wird sie mehrfach in die `woDetails`-Liste gepusht.

#### 5. **`KetPlanImport` Wochenerkennungs-Regex ist fragil**
`KetPlanImport.tsx:9-14` — `r.woNumber.match(/W(\d{2})/i)` matcht auch auf Substrings wie "OW12" oder "BOWL33". Die Erkennung sollte ein Wortgrenzen-Matching verwenden.

#### 6. **Kein Error Boundary in den UI-Komponenten**
Wenn `calcMap.get(row.key)` ein unerwartetes Shape zurückgibt (z.B. bei veralteten Firestore-Dokumenten), kann die gesamte UI crashen. Kein try/catch oder React Error Boundary vorhanden.

#### 7. **`parseDateShift` akzeptiert leere Strings ohne Warnung**
Gibt `{ date: "", shift: "" }` zurück — folgende `new Date("")` Calls in `fmtDateHeader` und `weekdayLabel` erzeugen ein "Invalid Date", das als `NaN` oder Fallback durch die App geistert.

### Verbesserungsvorschläge

1. **SHIFT_HOURS als geteilte Konstante** — aus `ketEquipmentSummary.ts` exportieren und in `KetEquipmentPanel.tsx` importieren statt erneut hart zu codieren.

2. **`runSharePct` dynamisch berechnen** — den tatsächlichen `firstRunPct`-Wert als Parameter an `computeFullResourceDemand` durchreichen.

3. **Defensive Checks in `parseDateShift`** — bei leerem Input einen Sentinel-Wert oder einen expliziten Fehler zurückgeben.

4. **Wochenerkennungs-Regex verbessern** — `\bW(\d{2})\b` statt `/W(\d{2})/i`.

5. **Deduplizierung in `woDetailsByStation`** — WO-Nummer als Set tracken, bevor sie hinzugefügt wird.
