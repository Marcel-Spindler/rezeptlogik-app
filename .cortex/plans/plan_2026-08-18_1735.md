## Auto-Snapshot Timeline mit Meal-Katalog-Integration

### Context

- Bestehendes Snapshot-System (`wmsSnapshots.ts`): speichert `SkuBilanzEntry[]` in localStorage (max 15)
- Live-Mode: refresht alle 30s, speichert aber keine Snapshots automatisch
- Meal-Katalog (`DataBundle.mealCatalog`): hat `mealId`, `photoUrl`, Rezeptcodes (FV/FE)
- `weekRecipes`: hat Slot-Zuordnung, Preference, Recipe-Code
- `MealOperation` (neu): hat jetzt `submeals: SubmealTrace[]` mit Gap-Status pro Station
- WorkorderRow: hat `mealItemNumber` (REC-xxx) und `mealItemDescription` (enthält FV/FE-Code)

### Implementation Steps

#### 1. Erweitertes Snapshot-Format (`wmsSnapshots.ts`)

Neuer Storage-Key `wms-timeline-v1` (separiert von manuellen Snapshots):

```ts
export type TimelineSnapshot = {
  id: string;
  timestamp: string;
  week: string;
  meals: TimelineMealState[];
};

export type TimelineMealState = {
  mealSku: string;
  mealName: string;
  recipeCode: string;       // "FV0713A" extrahiert aus mealItemDescription
  required: number;
  finished: number;
  readinessPct: number;
  submeals: {
    sku: string;
    name: string;
    required: number;
    total: number;
    gap: number;
    status: "ready" | "partial" | "missing";
    stationBreakdown: {
      platingHolding: number;
      postBlast: number;
      debox: number;
      staging: number;
      sleeving: number;
    };
  }[];
};
```

- `MAX_TIMELINE_SNAPSHOTS = 96` (48h bei 30min-Intervall)
- Auto-Cleanup: nur Snapshots der aktuellen Woche behalten

#### 2. Auto-Snapshot im Live-Mode (`WmsKwOverviewView.tsx`)

Im Live-Intervall (`liveIntervalRef`), nach erfolgreichem `doLoad`:
- `persistTimelineSnapshot(selectedWeek, mealOperations)` aufrufen
- Nur wenn sich der Zustand geändert hat (simpler Hash-Check der readinessPct-Werte)

#### 3. Neuer Timeline-Tab (`WmsTimelineView.tsx`)

Neuer CmdTab `"timeline"` mit:

**Header**: Horizontaler Zeitstrahl (scrollbar):
```
|──[06:00]──[06:30]──[07:00]──[07:30]──[08:00]──▼──[08:30]──|
                                         (aktuell)
```
- Punkte = Snapshots, farbig je nach Gesamt-Readiness (grün/amber/rot)
- Click setzt den "viewing" Zeitpunkt

**Hauptbereich**: Meal-Grid (konfigurierbar):
- Karten pro Meal mit:
  - FV/FE-Code (aus mealItemDescription geparst)
  - Meal-Name
  - Photo (aus `mealCatalog?.photoUrl` wenn verfügbar)
  - Readiness-Ring (0-100%)
  - Submeal-Ampel: grüne/gelbe/rote Dots
  - "Fertig" vs "Offen" Menge
- Sortierung: nach Gap (größte Lücke zuerst)

**Gap-Events-Feed** (toggle):
- Chronologischer Feed: "14:32 — SUB-013731 (Cabbage) fehlt seit PLH leer"
- Berechnet durch Diff zwischen aufeinanderfolgenden Snapshots
- Highlight: Items die von "ready" auf "missing" gewechselt haben

**Ansicht-Toggle** (oben rechts):
- "🎯 Meal-Grid" (Default): Karten mit Photos
- "📊 SKU-Flow": Tabelle mit allen Submeals über alle Stationen
- "🚨 Gap-Feed": nur Events wo etwas gefehlt hat

#### 4. Meal-Katalog-Matching

RecipeCode-Extraktion aus `mealItemDescription`:
```ts
function extractRecipeCode(desc: string): string | null {
  const m = desc.match(/\b(F[VE]\d{4}[A-Z]?)\b/);
  return m ? m[1] : null;
}
```

Dann Lookup in `DataBundle.recipes[recipeCode]` für:
- `baseName` (vollständiger Name)
- `catalog?.photoUrl` (Bild)
- `markets.DE.subRecipes` (strukturierte Sub-Rezepte)

#### 5. Persistierung und Cleanup

- localStorage Key: `wms-timeline-v1`
- Automatischer Cleanup: Snapshots älter als 48h entfernen
- Storage-Limit-Guard: wenn `localStorage.setItem` wirft, älteste 50% entfernen

### Verification

- Live-Mode starten → nach 2-3 Intervallen prüfen ob Timeline-Snapshots in localStorage
- Timeline-Tab öffnen → Zeitstrahl sollte Punkte zeigen
- Snapshot klicken → Meal-Grid zeigt den Zustand zu dem Zeitpunkt
- Meal-Karte zeigt FV-Code + Name + Readiness
- Gap-Feed zeigt Events wenn ein Submeal von "ready" → "missing" wechselt
