## Plan: WO-Instructions localStorage-Cache + Delta-Generierung

### Context
- `woInstructions` ist aktuell nur ein `useState<Record<string, WoInstruction>>({})` — geht bei Neuladen verloren
- Die `row.key` enthält einen Index (`csv::0::...`, `wo::3::...`) der instabil ist bei Neuimport
- Beim "Instructions erzeugen" werden ALLE Rows der gewählten Tage an Gemini geschickt, auch bereits generierte
- Equipment-Caps werden schon per localStorage gecacht — selbes Pattern für Instructions

### Implementation steps

**1. Stabilen Cache-Key für Instructions einführen** (`ketLogic.ts`)
- Neue exported Hilfsfunktion `instructionCacheKey(row: KetRow): string` → `${row.woNumber}::${row.subRecipeName}`
- Stabil über Neuimporte hinweg (WO-Nummer + Sub-Rezept bleibt gleich)

**2. Instructions in localStorage persistieren** (`KetBreakdownView.tsx`)
- Neuen `STORAGE_KEYS.woInstructions = "ket-wo-instructions-v1"` anlegen
- `woInstructions`-State initial aus localStorage laden (wie bei `csvRows`)
- Überall wo `setWoInstructions(...)` aufgerufen wird, parallel `storage.setItem` aufrufen
- Der Cache verwendet `instructionCacheKey` als Schlüssel (nicht den instabilen `row.key`)

**3. Mapping-Layer: row.key ↔ Cache-Key** (`KetBreakdownView.tsx`)
- Beim Laden: aus localStorage geladene Instructions per `instructionCacheKey` auf aktuelle `row.key`s mappen
- Beim Speichern: per `instructionCacheKey` in den Cache schreiben
- Dadurch überleben Instructions einen Neuimport mit neuen Index-basierten Keys

**4. Delta-Logik bei Batch-Generierung** (`KetBreakdownView.tsx`)
- `generateInstructionsForSelectedDays`: vor dem Senden an Gemini, bereits vorhandene Instructions rausfiltern
- Nur WOs ohne Instruction an `generateWoInstructionsBatch` geben
- Neuer Button-Text: z.B. "Instructions für 5 neue WOs erzeugen (12 bereits vorhanden)"
- Optional: "Alle neu generieren" force-Button für den Fall dass man bewusst alles refreshen will

**5. Cache-Verwaltung** (`KetBreakdownView.tsx`)
- "Cache leeren"-Button neben dem Generate-Button (für manuellen Reset)
- TTL/Limit: Cache auf max. 500 Einträge begrenzen (älteste raus), um localStorage nicht zu sprengen
