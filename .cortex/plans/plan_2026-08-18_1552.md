## Systematische Verbesserungen: Meal Katalog

### Kontext

Die `MealCatalogView` ist eine 224-Zeilen Single-File-Komponente, die den gesamten Verden Meal Database Katalog darstellt. Sie hat bereits gute `useMemo`-Nutzung, aber es fehlen mehrere Patterns, die andere Views im Projekt bereits verwenden.

---

### 1. Performance

| # | Problem | Lösung |
|---|---------|--------|
| 1.1 | **Keine Virtualisierung** — alle gefilterten Meals werden als DOM-Elemente gerendert. Bei 500+ Meals wird das spürbar. | `@tanstack/react-virtual` einsetzen (ist bereits installiert, wird in `RecipeList.tsx` genutzt). |
| 1.2 | **Kein Debounce auf Suche** — bei jedem Tastendruck wird die gesamte Filter-Pipeline ausgelöst. | Einfaches `useDebounce` (300ms) für den `query` State hinzufügen. |
| 1.3 | **`findWeekMatches` wird für jedes Meal aufgerufen** — bei `weekMeals` und `futureMeals` wird für jedes Meal über alle `weekRecipes` iteriert. | Einmalig einen `Map<mealId, Set<week>>` Index aufbauen statt O(meals × weekRecipes) Suche. |

---

### 2. UX / Interaktion

| # | Problem | Lösung |
|---|---------|--------|
| 2.1 | **Keine Keyboard-Navigation** — anders als `RecipeList.tsx` (Arrow Keys) gibt es keine Tastatursteuerung. | Arrow Up/Down für Liste, Escape zum Fokus auf Suchfeld. |
| 2.2 | **Kein Export** — andere Views bieten XLSX/CSV-Export. Der Katalog hat keine Export-Möglichkeit. | "Export als XLSX"-Button (Nährwerte + Metadaten der gefilterten Meals), nutzt bestehendes `exceljs`-Pattern. |
| 2.3 | **Kein Loading State** — wenn der Katalog noch lädt, erscheint nur eine harte Meldung. | Loading-Skeleton analog zu `PlanningOasisView` Suspense-Pattern einbauen. |
| 2.4 | **Keine Empty-State-Differenzierung** — "Nicht gefunden" sieht gleich aus egal ob Filter zu eng oder keine Daten. | Unterschiedliche Meldungen: "Keine Treffer für Filter" vs. "Keine Meals in dieser Woche". |

---

### 3. Fehlende Features

| # | Feature | Beschreibung |
|---|---------|-------------|
| 3.1 | **Sortierung** | Aktuell nur alphabetisch. Zusätzliche Optionen: nach Kalorien, Gewicht, Cuisine, Status. |
| 3.2 | **Multi-Tag-Filter** | Aktuell nur ein Tag gleichzeitig wählbar. Multi-Select ermöglichen (UND-Verknüpfung). |
| 3.3 | **Favoriten / Merkliste** | Per localStorage Meals markieren für schnellen Zugriff. |
| 3.4 | **Deep-Link / URL-State** | Ausgewähltes Meal + Filter in URL speichern, damit Links teilbar sind. |
| 3.5 | **Vergleichsmodus** | 2-3 Meals nebeneinander (Nährwerte, Spezifikation) vergleichen. |

---

### 4. Code-Qualität

| # | Problem | Lösung |
|---|---------|--------|
| 4.1 | **Alles in einer Datei** | Aufteilen in: `MealCatalogView.tsx` (Container), `CatalogBrowser.tsx` (Sidebar), `CatalogDetail.tsx` (Detail), `CatalogHero.tsx` (Header), `catalog-utils.ts` (Helper). |
| 4.2 | **Sub-Komponenten nicht memoized** | `InfoBlock`, `ProductionMatch` mit `React.memo` wrappen. |
| 4.3 | **Inline-Logik im JSX** | Zeile 196 (Metrics Array), Zeile 202-205 (Recipe Lookup) in eigene Variablen/Komponenten extrahieren. |
| 4.4 | **Fehlende TypeScript-Strenge** | `field()` und `metric()` könnten typsichere Sheet-Keys haben statt lose Strings. |

---

### 5. Accessibility

| # | Problem | Lösung |
|---|---------|--------|
| 5.1 | **Liste hat keine ARIA-Rolle** | `role="listbox"` auf `.catalog-list`, `role="option"` + `aria-selected` auf Einträge. |
| 5.2 | **Fehlende `aria-live` Region** | Filteranzahl-Anzeige als `aria-live="polite"` für Screenreader. |
| 5.3 | **Kein Focus-Management** | Bei Auswahl-Wechsel den Detail-Bereich nicht fokussieren → Tab-Trap möglich. |

---

### 6. Robustheit

| # | Problem | Lösung |
|---|---------|--------|
| 6.1 | **Kein Error Boundary** | Fehlende/kaputte Katalog-Daten crashen die ganze App. Einen `ErrorBoundary` um die View wrappen. |
| 6.2 | **Bildlade-Fehler unbehandelt** | `<img>` ohne `onError` Handler → Broken Image Icon. Fallback auf `catalog-art` bei Fehler. |
| 6.3 | **Keine Daten-Validierung** | `sheets` könnte `undefined` sein bei korruptem JSON. Defensive Guards an kritischen Stellen. |

---

### Implementierungsreihenfolge (vorgeschlagen)

1. **File-Split** (4.1) — Grundlage für alles Weitere
2. **Virtualisierung** (1.1) + **Debounce** (1.2) — größter Performance-Gewinn
3. **Keyboard-Navigation** (2.1) + **Accessibility** (5.x)
4. **Sortierung** (3.1) + **Multi-Tag** (3.2) — schnelle UX-Wins
5. **Export** (2.2) — nutzt bestehende Patterns
6. **Bild-Fehlerbehandlung** (6.2) + **Error Boundary** (6.1)
7. **Favoriten** (3.3) + **URL-State** (3.4) + **Vergleich** (3.5) — größere Features
