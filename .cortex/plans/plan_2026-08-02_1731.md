## Context

**Erkenntnisse:**
- Die App hat 7 WMS-Endpoints (Plating, Staging, Debox, Postblast, Sleeving, Inbound, Workorders)
- Work Orders (z.B. `32-81`) werden über `CONTROL_NUMBER` in `T_TRAN_LOG` mit allen physischen Bewegungen verknüpft
- `V_SUBMEAL_PRODUCTION` enthält WO-Stammdaten (Items, Mengen, Status, MHD)
- `T_TRAN_LOG.CONTROL_NUMBER` = WO-Nummer → enthält den gesamten Lifecycle: Allocation → Picking → Debox → Kitchen → Preblast → Postblast → Close
- Die `WmsKwOverviewView` aggregiert bisher nach SKU, zeigt aber keine WO-zentrierte Ansicht
- Join-Keys: `ITEM_NUMBER` (SKU), `CONTROL_NUMBER` (WO), `LOT_NUMBER` (Los)

**24 verschiedene Transaktionstypen pro WO** (370=Allocation, 371=Release Picking, 380/381=Pick/Put, 386=Debox QC, 393=Staging→Debox, 650=Postblast, 651=Preblast LP Created, 660=KITCHENWIP Adj, 661=Close WO, etc.)

## Implementation Steps

### 1. Neuer API-Endpoint: `/api/wms-wo-detail`

**Datei:** `scripts/wms-local-server.ts`

Neuer SQL + Endpoint der alle Transaktionen für eine bestimmte WO-Nummer (oder alle WOs der KW) aus `T_TRAN_LOG` via `CONTROL_NUMBER` holt:

```sql
SELECT CONTROL_NUMBER AS WO_NUMBER, TRAN_TYPE, DESCRIPTION, ITEM_NUMBER,
       TRAN_QTY, LOT_NUMBER, LOCATION_ID, LOCATION_ID_2, HU_ID,
       START_TRAN_DATE, END_TRAN_DATE, EMPLOYEE_ID
FROM US_OPS_ANALYTICS.HIGHJUMP.T_TRAN_LOG
WHERE WH_ID = ?
  AND CONTROL_NUMBER LIKE ?  -- z.B. '32-%' für KW32
  AND START_TRAN_DATE >= TO_TIMESTAMP_NTZ(?)
  AND START_TRAN_DATE < TO_TIMESTAMP_NTZ(?)
ORDER BY CONTROL_NUMBER, START_TRAN_DATE
LIMIT ?
```

### 3. WO-zentrierte Ansicht in `WmsKwOverviewView`

**Erweitert die bestehende `WmsKwOverviewView.tsx`:**

- **WO-Spalte in allen Stations-Tabellen:** Alle `AggStoredRow`/`AggSleevingRow`-Tabellen bekommen eine neue Spalte "WO", die zeigt, welcher Work Order ein Item zugeordnet ist (Join über `ITEM_NUMBER`)
- **WO-Detail-Panel** (neues Overlay, ähnlich wie `SkuDetailPanel`): Klick auf eine WO-Nummer öffnet ein Panel mit:
  - **Header:** WO-Nummer, Meal-Name, Status, KW, MHD
  - **Timeline/Lifecycle:** Alle 24 Transaktionstypen als chronologische Timeline (Allocation → Picking → Debox → Kitchen → Preblast → Postblast → Close)
  - **Submeal-Breakdown:** Welche Submeals/Items gehören zur WO
  - **Mengen-Übersicht:** Soll vs. Ist (geplant aus V_SUBMEAL_PRODUCTION vs. tatsächlich bewegt in T_TRAN_LOG)
  - **MHD-Warnung:** Wenn Expiry < 3 Tage → rot markiert
  - **Cross-Station-Trace:** Wo befindet sich das Material aktuell (aus T_STORED_ITEM via ITEM_NUMBER)
  - **Discrepancies/Missstände:** Mengenabweichungen, WIP-Reconciliation-Einträge, abgelaufene MHD
  - **Mitarbeiter:** Wer hat welche Transaktion durchgeführt
