## Implementierung

### 1. WO-Nummer auf jeder Seite (Komponenten-Header)
- In `buildComponentsHtml`: Vor jedem `component-block` den WO-Ref als kleine Zeile einfügen: `WO {woNumber} · {recipeCode} · {subRecipeName}`
- CSS-Klasse `.component-wo-ref` mit kleiner Schrift (8px), wird nur in `@media print` sichtbar

### 2. Erste Seite drastisch kompakter
- `.wo-num`: 28px → 14px (print: 12px)
- `.sub` (Sub-Rezept-Name): 18px → 11px, padding reduziert
- `.sval.big` (Batch-Zahl): 18px → 12px
- `.stats` Grid: `gap:4px` → `gap:2px`, padding auf Stats verkleinern
- `.methods` (Cook-Methods-Leiste): padding 9px 14px → 4px 8px, font-size 12px → 9px
- Equipment-Batch-Tiles: font-size runter (18px → 12px), padding halved
- `.slabel`: 6.5px → 5.5px
- `.date-tag`, `.rname`: kompakter
- Badges/Allergen/Chiller: margin reduziert

### 3. Scoops auf Sub-Meals
- Bereits implementiert (Zeile 142-144). Scoop-Badge wird gerendert falls `component.scoopInfo` vorhanden. Keine Code-Änderung nötig hier — funktioniert bereits.

### 4. Minimale Seiten, nie ein Sub-Meal durch Umbruch trennen
- **Entferne** `.components-title{page-break-before:always}` — Komponenten starten direkt nach der Übersicht
- **Entferne** `.component-block+.component-block{page-break-before:always}` — kein erzwungener Umbruch zwischen Komponenten
- **Behalte** `.component-block{page-break-inside:avoid;break-inside:avoid-page}` — ein Block darf nie INNERHALB brechen
- Effekt: Komponenten fließen natürlich auf so wenig Seiten wie möglich, aber ein einzelner Block reißt nie durch einen Seitenumbruch
