## Context

Die App nutzt bereits **Firebase Cloud Functions** mit **Snowflake Keypair-Auth** (`SNOWFLAKE_JWT`) fuer alle WMS-Endpoints. Die Infrastruktur (Service Account, Private Key als env var, `connectSnowflake()`, `executeSnowflakeQuery()`) ist komplett vorhanden. Die App hat ein Surface-Konzept (`?surface=kitchen`, `?surface=rundmail`) das eigenstaendige Views ohne die volle App rendert.

**Plan:** Neuer `?surface=redzone` Modus + Cloud Function `redzoneStatus` die dasselbe SQL gegen Snowflake ausfuehrt. Damit kann jeder mit dem Link `https://rezeptlogik-verden-factor.web.app/?surface=redzone` das Redzone-Dashboard sehen — ohne lokalen Server, ohne Snowflake-Login.

---

## Implementation Steps

### 1. Cloud Function hinzufuegen
**File:** `functions/index.js`

Neue SQL-Konstante `REDZONE_STATUS_SQL` (identisch mit der im lokalen Server) + neuer Export `redzoneStatus`:
```js
exports.redzoneStatus = onRequest({ region: "europe-west3", timeoutSeconds: 60 }, async (req, res) => { ... });
```
Nutzt `connectSnowflake()` + `executeSnowflakeQuery()` — exakt dasselbe Pattern wie `wmsPlating` etc.

### 2. Firebase Hosting Rewrite
**File:** `firebase.json`

Neuen Rewrite vor dem Catch-all:
```json
{ "source": "/api/redzone-plating-status", "function": "redzoneStatus", "region": "europe-west3" }
```

### 3. Surface "redzone" registrieren
**File:** `src/app/AppContext.tsx`

- `AppSurface` Type erweitern: `"full" | "kitchen" | "rundmail" | "redzone"`
- `resolveSurface()`: `if (s === "redzone") return "redzone";`

### 4. Router: Redzone-Surface rendern
**File:** `src/app/Router.tsx`

Neuer Block im Router (vor `kitchenMode`):
```tsx
if (surface === "redzone") {
  return (
    <Shell>
      <RedzoneLiveView />
    </Shell>
  );
}
```
Das rendert NUR das Redzone-Dashboard — keine Sidebar, kein WeekSelector, kein DataBundle noetig.

### 5. RedzoneProvider: DataBundle-Abhaengigkeit entfernen
**File:** `src/app/App.tsx`

`RedzoneProvider` ist bereits um alles gewrapped und funktioniert ohne DataBundle — es fetcht direkt von `/api/redzone-plating-status`. Im Surface-Mode ist kein AppData noetig.

### 6. Vite Proxy beibehalten (Dev-Modus)
Bereits eingerichtet — lokal geht `/api/redzone-plating-status` zum lokalen Server, deployed geht es zur Cloud Function.

## Verification

1. `firebase deploy --only functions:redzoneStatus` → Function deployed
2. `firebase deploy --only hosting` → Hosting deployed
3. Browser: `https://rezeptlogik-verden-factor.web.app/?surface=redzone` → zeigt das Redzone-Dashboard ohne Login
4. Lokal: `npm run dev` → `http://localhost:5173/?surface=redzone` → zeigt das Dashboard via lokalen Server
