## Context

**Datenquellen:**
- **PET-CSV** (`PET-Verden-2026-W35.csv`): Enthält pro Tag alle Rezepte mit Target-Portionen die geplated werden müssen. Format: `Production Shift` = `"2026-08-18 - 1"` (Datum + Schicht), `Recipe Name` = `"FV0713A - Cabbage in cheese sauce..."`, `Recipe WO Target` = Portionen
- **Allergen-Daten**: `recipe.markets[market].allergens` (String: "MILCH, SELLERIE, ...") + `structures[code].markets[market]` → DetailedSubRecipe-Baum mit Ingredient-Level `allergen`-Tags
- **Cup-Detection**: `recipe.catalog?.sheets["Verden Meal Database"]["Cup"] === "Yes"` oder über `compartmentName` in RecipeMarketDetails
- **Fisch-Detection**: Bestehende `detectSeafoodByName()` Heuristik

**Algorithmus-Ziel:**
- **Linie 1 (Highrunner)**: Höchstes Volumen, wenige Wechsel, möglichst gleiche Allergene → läuft durch
- **Linie 2 (Flexibel)**: Mittlere Rezepte, mehr Wechsel erlaubt, aber Allergen-Wechsel minimieren
- **Linie 3 (selten)**: Nur wenn Tages-Target es erzwingt (>~16.000 Portionen/Tag)
- **Cupping**: Rezepte mit Cup werden identifiziert und in die "Cupping/Slicing"-Spalte im Sheet eingetragen (parallel zur Linie, aber eigenständig)
- **Allergen-Sortierung**: Rezepte mit gleichen Allergenprofilen nacheinander auf derselben Linie → minimiert Reinigungspausen

## Implementation Steps

### 1. Neues Modul: `src/features/planning-oasis/lines/autoPlatingAlgorithm.ts`

Der Kern-Algorithmus mit folgender Logik:

```
Input: PET-CSV-Daten (day → recipes[]), Recipe-Allergen-Map, Cup-Map
Output: ScheduleMap (day|slot|line → recipe)

Pro Tag:
1. Rezepte nach Volumen sortieren (desc)
2. Allergen-Profil extrahieren (Set<string> pro Rezept)
3. Allergen-Ähnlichkeit berechnen (Jaccard-Similarity)
4. Clustering: Greedy-Grouping nach Allergen-Ähnlichkeit
   - Gruppe A: Größte Cluster (ähnliche Allergene + höchstes Volumen) → Linie 1
   - Gruppe B: Restliche Rezepte → Linie 2
   - Gruppe C: Nur wenn Total > Threshold (z.B. 16k) → Linie 3
5. Innerhalb jeder Gruppe: Reihenfolge optimieren (TSP-Greedy) 
   - Minimize allergen changeovers (Anzahl neuer Allergene zum Vorgänger)
   - Seafood immer am Ende (MHD-konform)
6. Zeitslots füllen: Portionen / Linienkapa = benötigte Stunden
7. Cupping-Spalte: Rezepte mit hasCup parallel zuordnen
```

### 2. Allergen-Utility: `extractAllergenProfile(recipe, data)` 

Extrahiert ein normalisiertes `Set<string>` mit Allergen-Kategorien (die 10 aus dem AM-Dictionary) für ein Rezept. Nutzt:
- Primär: `data.recipes[code].markets.DE.allergens` → parse comma-separated
- Fallback: `data.structures[code]` → walk sub-recipe tree

### 3. Cup-Utility: `hasCup(recipe, data)` 

Prüft ob ein Rezept einen Cup-Schritt hat:
- `data.recipes[code].catalog?.sheets["Verden Meal Database"]["Cup"] === "Yes"`
- Fallback: `compartmentName` enthält "cup" (case-insensitive)

### 4. PET-CSV-Parser: `parsePetCsv(text)` 

Parst die PET-CSV und gibt `Map<PlanDay, PetDayRecipe[]>` zurück:
- Datum → Wochentag-Mapping
- Extrahiert Code aus "Recipe Name" (Regex: `FV\d{4}[A-Z]`)
- Target-Portionen aus "Recipe WO Target"

### 5. Integration in `LinePlatingSheet.tsx`

- Neuer Button "Auto-Plating (PET)" der einen File-Upload triggert
- Nach Upload: PET-CSV parsen → `autoPlatingAlgorithm()` ausführen → Schedule befüllen
- Sheet-Ansicht zeigt das Ergebnis direkt im GSheet-Format
- Cupping-Spalte wird automatisch befüllt

### 6. Integration in `LinePlanningView.tsx`

- Neuer Button neben "Auto-Plan": "Smart Plating (PET)" 
- Upload-Dialog für PET-CSV
- Ergebnis wird in den bestehenden `schedule` State geschrieben
- Funktioniert mit dem Tab-Switcher (Sheet-Ansicht zeigt optimiertes Layout)
