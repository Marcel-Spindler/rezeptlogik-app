## Context

**Ursachen für die wiederkehrenden Fehler:**
1. **~30 dynamische Firebase-Imports** (`await import("./core/firebase")` + `await import("firebase/firestore")`) brechen sporadisch im Vite Dev-Server. Firebase v11 + Vite Dynamic Imports ist unzuverlässig.
2. **Manuelle Pipeline**: Nach `import:local` (→ data.json) muss man manuell `db:build` ausführen, weil die App aus SQLite liest (`VITE_DATA_SOURCE=local-db`). Das vergisst man jedes Mal.
3. **Dev-Server-UI-Import** (`/api/import-local` in vite.config.ts) ruft nur `npm run import:local` auf, aber nicht `db:build` danach — die App zeigt danach alte Daten.

## Plan

### 1. Zentrales Firebase-Modul mit statischen Exports (`src/core/firebase.ts`)

Erweitere `firebase.ts` um **alle benötigten Firestore-Funktionen** als re-exports, damit kein Modul mehr `await import("firebase/firestore")` braucht:

```ts
// firebase.ts
import { initializeApp, type FirebaseApp } from "firebase/app";
import { getFirestore, type Firestore, doc, collection, writeBatch, 
         setDoc, getDoc, getDocs, onSnapshot } from "firebase/firestore";

export { doc, collection, writeBatch, setDoc, getDoc, getDocs, onSnapshot };
// ... getFirebase() bleibt gleich
```

### 2. Alle dynamischen Imports eliminieren (6 Dateien)

Ersetze in allen Dateien die `await import(...)` Pattern durch statische Imports von `./core/firebase`:

- `src/core/dataSource.ts` (2 Stellen)
- `src/lib/wmsCache.ts` (1 Stelle)
- `src/LinePlanningView.tsx` (8 Stellen)
- `src/PlanningView.tsx` (3 Stellen)
- `src/RackV2View.tsx` (3 Stellen)
- `src/ShareDashboard.tsx` (1 Stelle)

Pattern vorher:
```ts
const [{ getFirebase }, { doc, setDoc }] = await Promise.all([
  import("./core/firebase"),
  import("firebase/firestore"),
]);
const { db } = getFirebase();
```

Pattern nachher:
```ts
import { getFirebase, doc, setDoc } from "./core/firebase";
// ... innerhalb der Funktion:
const { db } = getFirebase();
```

### 3. Import-Pipeline automatisieren (`scripts/import-local.ts`)

Am Ende von `import-local.ts` (nach dem Schreiben der `data.json`) automatisch `db:build` ausführen mit `execSync`:

```ts
// Am Ende von main():
import { execSync } from "node:child_process";
console.log("Rebuilding local SQLite database…");
execSync("node scripts/local-db.mjs", { cwd: process.cwd(), stdio: "inherit" });
```

### 4. Vite-Plugin `/api/import-local` anpassen

Im `importLocalPlugin()` den Befehl von `npm run import:local` auf `npm run import:local && npm run db:build` ändern — damit auch der UI-Button immer die vollständige Pipeline durchläuft. (Alternativ: wird durch Schritt 3 abgedeckt, da import:local dann selbst db:build aufruft.)

### 5. Verification

- `npx tsc --noEmit` — keine Compile-Fehler
- `npx vite build` — Production-Build erfolgreich
- Dev-Server starten, CSV-Import in der UI testen — kein "Failed to fetch dynamically imported module" mehr
- Rezeptstruktur-Tab für beliebiges Rezept zeigt Daten
