## Equipment-Aggregations-Helper: `ketEquipmentSummary.ts`

**Idee:** Eine reine Logik-Datei (kein React, kein UI), die alle WOs einer Auswahl (Tag, Schicht, Run, ganze Woche) durchrechnet und ein **Equipment-Demand-Summary** liefert — wie ein "Maschinenpark-Stundenplan". Später direkt in die Rundmail einbettbar.

### Was es liefert

```ts
interface EquipmentDemandSummary {
  // Pro Tag + Schicht
  byDayShift: DayShiftEquipDemand[];
  // Wochenübersicht (Peaks)
  weekPeaks: EquipPeakInfo[];
  // Engpass-Warnungen (Auslastung > Threshold)
  bottlenecks: BottleneckWarning[];
}

interface DayShiftEquipDemand {
  date: string;
  shift: string;
  shiftLabel: string;        // "Frühschicht (06:00–14:00)"
  equipment: EquipSlot[];    // jedes Equipment mit aggregierten Batches/Stunden
  totalKg: number;           // Gesamtmenge aller WOs dieses Tages
  woCount: number;
}

interface EquipSlot {
  equip: string;             // "BRAISER"
  label: string;             // "Braiser"
  totalBatches: number;      // Summe aller Batches dieses Equipments an dem Tag
  totalKg: number;           // Gesamtes kg durch dieses Equipment
  peakCapacityKg: number;    // größte Einzel-WO-Kapazität (= engster Flaschenhals)
  estimatedMinutes: number;  // Batches × Default-Minuten-pro-Batch (Braiser ~45min, Oven ~35min, etc.)
  woNumbers: string[];       // welche WOs dieses Equipment brauchen
}

interface EquipPeakInfo {
  equip: string;
  label: string;
  peakBatches: number;       // Maximum-Tag
  peakDate: string;
  avgBatchesPerDay: number;
}

interface BottleneckWarning {
  date: string;
  shift: string;
  equip: string;
  totalBatches: number;
  estimatedHours: number;
  shiftHoursAvailable: number; // 8h
  reason: string;              // z.B. "Braiser: 14 Batches ≈ 10.5h — übersteigt 8h-Schicht"
}
```

### Implementierung

**Neue Datei:** `src/features/ket-plan/ketEquipmentSummary.ts`

1. **Eingabe:** `KetRow[]` + `BatchCalc`-Ergebnisse (Map<string, BatchCalc>) + Caps
2. **Gruppierung** nach `(date, shift)` — nutzt den bestehenden `parseDateShift()`
3. **Aggregation** pro Equipment: summiert `equipBatches` aller WOs dieses Tages
4. **Zeitschätzung** mit konfigurierbaren Minuten-pro-Batch (Default: Braiser 45, Oven 35, Planetary 15, etc.)
5. **Engpass-Erkennung**: wenn geschätzte Stunden > Schicht-Fenster (8h) → Warning
6. **Peak-Erkennung**: höchster Equipment-Tag der Woche

### Warum cool

- Sofort zeigt: "Montag Frühschicht braucht 14× Braiser-Durchlauf = ~10.5h — geht sich mit einem Braiser nicht in einer Schicht aus"
- Wochenüberblick: "Dienstag ist der Equipment-Spitzentag"
- Für die Rundmail ideal: ein kompaktes HTML-Snippet (Equipment-Heatmap / Tabelle) pro Tag
- Keine UI-Abhängigkeit — reiner Helper, testbar
