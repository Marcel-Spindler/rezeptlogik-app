## Context

**Ergebnis der Exploration:**
- Redzone-Daten für **Factor Verden** sind in Snowflake verfügbar: `REDZONE_AWS_EUWEST1_HELLOFRESH_EXTERNAL_SHARE."hellofresh-org"` — die Enterprise heißt "Factor Verden"
- Die View `v_shiftrunsegment` enthält für den Bereich **"Plating"** die fertigen Meals mit `productTypeName` (z.B. "FV1404A Bulgogi Shredded Beef Bowl [DE]"), `productTypeSKU` (REC-Code), `outCount`, `startTime`, `endTime`
- Alle Bereiche (Ovens, Braisers, Plating etc.) sind verfügbar — man sieht also den gesamten Produktionsfluss
- Die App nutzt einen **lokalen Snowflake-Server** (`scripts/wms-local-server.ts`, Port 3141) mit SSO-Auth für Live-Queries
- Views werden als `AppView`-Type registriert und im Router gemapped
- Pattern: View-Datei (TSX) + optionaler Feature-Ordner unter `src/features/`

**SQL für den Live-Status (getestet, funktioniert):**
```sql
SELECT "areaName", "locationName", "productTypeName", "productTypeSKU", 
       "outCount", "inCount", "startTime", "endTime"
FROM "REDZONE_AWS_EUWEST1_HELLOFRESH_EXTERNAL_SHARE"."hellofresh-org"."v_shiftrunsegment"
WHERE "enterpriseUUID" IN (
  SELECT "enterpriseUUID" FROM ...v_enterprise WHERE "enterpriseName" = 'Factor Verden'
)
AND "areaName" = 'Plating'
AND "productTypeName" IS NOT NULL AND "productTypeName" != 'None'
ORDER BY "startTime" DESC
```

## Implementation Steps

### 1. Backend: Neuen Endpoint im WMS-Server hinzufügen
**Datei:** `scripts/wms-local-server.ts`

- Neue SQL-Konstante `REDZONE_PLATING_STATUS_SQL` — holt die letzten Plating-Runs für Verden (heute + gestern)
- Optionaler zweiter Query für den gesamten Produktionsstatus (Ovens, Braisers = "in Arbeit")
- Neuer Endpoint: `GET /redzone-plating-status` → gibt JSON mit Plating-Runs zurück
- Row-Mapper: `mapRedzoneRunRow`

### 2. Vite Proxy konfigurieren
**Datei:** `vite.config.ts`

- Neuen Proxy-Eintrag: `"/api/redzone-plating-status"` → `http://127.0.0.1:3141`

### 3. Feature-Modul anlegen
**Neuer Ordner:** `src/features/redzone-live/`

- `redzoneTypes.ts` — TypeScript-Interfaces für die Redzone-Daten
- `useRedzoneStatus.ts` — Custom Hook: Polling alle 60s, Fetch vom Endpoint
- `RedzoneLiveView.tsx` — Haupt-View mit:
  - **Aktiv-Plating** (was gerade auf den Lines läuft)
  - **Fertig heute** (abgeschlossene Runs, outCount > 0)
  - **Zusammenfassung** (Total Meals plated heute)

### 4. App-Integration (View registrieren)
- `src/app/AppContext.tsx` — `"redzone-live"` zu `AppView` Type hinzufügen
- `src/app/Router.tsx` — Import + Switch-Case für die neue View
- `src/app/NavTabs.tsx` — Neuer Tab-Eintrag "Redzone Live"
