Factor — Automated Production Recipe Sheets

Project handover for IT · prepared by Matteo Spessotto (Executive Chef) · for Osama (IT Manager)

In one line: a small tool that reads the daily plan in HelloFresh (RTE Execution Tracking + Manufactured SKU) and automatically generates the kitchen's production recipe sheets (PDF) — batches, work orders, ingredients, EN/DE cooking instructions, allergens — saving them to a shared Drive. It should run unattended every day at 13:00 and 17:00. The logic is built and validated; it needs an environment set up (this document) to run on its own.

1. The goal

Today the chef manually reads the planning department's daily work orders, calculates how to split each recipe into batches (by equipment capacity), and prints a production sheet per work order. This is repetitive and time-sensitive (new work orders and reworks appear through the day). We automated it end-to-end.

2. What it produces

One clean production sheet per Work Order (WO), one WO per page (for the Spice Room), in an English layout. Each sheet contains:

  • Batches (count × kg, rounded up) — computed by HelloFresh
  • WO number and cook method / station sequence
  • Ingredients with quantity per batch & total (grams when < 1 kg)
  • Nested sub-recipes expanded with their own ingredients & instructions
  • Cooking instructions in English + German
  • Allergens highlighted (red = contains, amber = traces)
  • Spice-room ingredients underlined; "SEPARATE" tags; RTI (ready-to-eat) items flagged

Validated examples were generated on the chef's Desktop (recipe FV4064A "Ginger Garlic Chicken", plus a partial-rework sheet for FV4063A "Cheddar Pulled Beef").

3. How it works (technical)

  • A small Node.js + Playwright script (folder factor-recipe-bot).
  • It reuses a HelloFresh login (Azure AD) in a persistent browser profile — it stores no password and creates no new credentials.
  • On HelloFresh it only reads planning/recipe data via the site's own internal APIs (rte-execution-tracker, manufactured-sku-service, incl. the existing bulk/pdf-export endpoint) — it does not modify anything.
  • It renders each sheet to PDF locally (headless Chromium) and saves it to a shared Google Drive folder. All data stays internal: HelloFresh → local machine → company Drive.
  • Reworks: a state file records already-generated WOs; each run only creates sheets for new WOs (full re-cooks and partial reworks), labeled Run 1, Run 2…
  • Schedule: Windows Task Scheduler triggers the script at 13:00 and 17:00.

5. What we need from IT action

  1. A machine that stays on during the day to run the task at 13:00 and 17:00 (Matteo's PC is fine, or a small VM/server if preferred).
  2. Install Node.js 18+ on it (needs admin rights). Verify with node -v.
  3. In the factor-recipe-bot folder: 
    npm install
npx playwright install chromium
  4. One-time HelloFresh login: node bot.mjs --login → a browser opens, sign in to HelloFresh (Azure AD, incl. MFA), then close. The session is saved locally and reused.
  5. Create a Google Shared Drive named "Kitchen Recipes Workload" for the team, and make sure Google Drive for Desktop is installed on the machine so the tool can save PDFs into the synced folder. Set that path in bot.mjs (CONFIG.outDir).
  6. Windows Task Scheduler: two daily jobs (13:00 and 17:00) that run run.bat in the folder.
  7. Confirm it is acceptable to keep a persistent HelloFresh session on that machine — or advise if a dedicated service account is preferred.

Estimated setup: ~30 minutes together for install + first run + tuning.

6. Security & data notes

  • Uses the chef's own HelloFresh access — same as him using the site in a browser. No passwords are stored by the tool; it reuses the browser's Azure AD session.
  • Read-only on HelloFresh (planning/recipe data + the existing PDF-export endpoint). It does not change any HelloFresh data.
  • Output (PDFs) stays inside the company — saved to the company Google Shared Drive. Nothing is sent to third parties.
  • Open questions for IT: preferred host machine, and whether a service account should be used instead of a personal session.
